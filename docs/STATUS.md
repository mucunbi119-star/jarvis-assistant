## 確認の扱い

- ローカルの自動テストは保存・編集・削除、資料・表の生成、入力検証、未設定・失敗の扱いを確認します。
- ブラウザでのデモ確認は画面とローカル機能の確認です。実検索・OpenAI・Google の成功としては扱いません。
- Windows 用バッチファイルを用意していますが、クラウド環境は Linux のため Windows 実機でのダブルクリック起動は未確認です。
- `scripts/run.py` はローカルサーバーの応答を確認してからブラウザを開きます。ポートが使用中なら別のサービスを勝手に開かず停止します。
- Linux 上でランチャーのサーバー起動、`/api/health` の正常応答、Ctrl+C による終了、ポート重複時の拒否を実行して確認しました。Windows のバッチ実行とブラウザの自動起動そのものは未確認です。

コードを追加・変更した後は `python -m unittest discover -s tests -v` を再実行してください。

## Windows起動ファイルの修正（2026-10-29）

利用者から、Pythonが検出されない際に日本語の案内文の断片がコマンドとして実行される報告がありました。旧版GitHub ZIPを実際に取得すると改行はCRLFでした。改行異常という当初の推測は訂正します。日本語の表示文がCMDで誤って実行される原因は実機なしでは断定できませんが、文字コードの影響を避けるためバッチをASCII・CRLFに固定し、日本語ガイドを別のHTMLへ分離しました。既存の仮想環境が実行できるか確認し、作成とインストールの終了コードを判定します。Python未検出時は同梱の日本語ガイドをブラウザで開きます。旧版のUTF-8バッチは置き換えてください。Windows実機でのCMD実行は引き続き未確認です。

修正版は配布物の2テストを追加しています。作業ファイル、一時Gitリポジトリの保存内容、ZIPの各バッチがASCII・BOMなし・CRLFであることと、日本語ガイドの同梱を確認します。Gitの改行属性だけに依存しない検証です。
